# Reproducibility Package: Glioma Grading Machine Learning Analysis

This repository contains the complete analysis pipeline, code, and results for:

> **Cost sensitive machine learning triage for glioma grading using a minimal mutation and age panel**
> Singh, S., Pal, A., Mittal, N., Kaur, J., & Gared, F.
> *Scientific Reports* (under review)

It is provided as Supplementary Material S2 and is intended to let a reader reproduce every table, figure, and number reported in the manuscript directly from the raw, publicly available data.

---

## 1. Overview

The analysis classifies the legacy LGG-versus-GBM label in the UCI Glioma Grading Clinical and Mutation Features Dataset using 20 somatic mutation markers and 3 clinical variables. The pipeline compares four imbalance-handling strategies and four classifier families under nested cross-validation restricted to a training partition, locks one primary model by a pre-specified rule, and evaluates it once on a sealed test set. Full methodological detail is in the manuscript (Sections 4–5); this document covers what's needed to run it, not why it's designed this way.

- One further duplicate patient record (byte-identical across all 24 fields) was identified during our own audit and removed, giving the final analysis cohort of **n = 838** (Section 3).

## 5. Reproducing the Analysis

1. Install dependencies (Section 4) and place both data files in `data/` (Section 3).
2. Run the notebook top to bottom. Cells check for cached intermediate results (in `Results/Models/*.pkl`) and skip recomputation where a cache exists; delete the relevant `.pkl` file to force a rerun of that section.
3. Total runtime from a clean cache is approximately **35–50 minutes** on a standard multi-core machine, dominated by the nested-CV hyperparameter search (Section 4, Table 5) and its five-repeat robustness check (Section 5.10).
4. Every table and figure writes directly to `Results/Tables/` and `Results/Figures/`, overwriting the versions included in this package.

No manual steps, no hidden preprocessing scripts, and no cell needs to be run out of order — the notebook enforces its own execution order internally (Section 4.1, "test set touched once" rule) and will raise an assertion error rather than silently proceed if a section tries to access data it shouldn't yet have.

## 7. Reproducibility Notes and Known Sensitivities

This section exists because we found something worth disclosing rather than hiding, and a future user of this code should know about it before assuming a mismatch is their mistake.

**Headline discrimination is stable across environments; several near-tied downstream values are not.** Re-running this exact notebook, on the identical SHA-256-verified dataset and the identical random seed (42), on the cross-check environment in Section 4 reproduced the paper's headline AUC and sensitivity closely (AUC 0.930 vs. 0.926 canonical; sensitivity 0.930 in both) but shifted several values that were already close to a tie in the primary run:

- **Imbalance-strategy lock** (Table 4): "No resampling" and "Class-weight" are separated by 0.0001 mean AUC in the primary run; in the cross-check run, the tie flips.
- **Primary-vs-alternative model disagreement** (Section 5.3, Table 6): the primary run's mean-of-fold and pooled-OOF statistics disagree about which model wins (motivating the parallel logistic-regression analysis in Section 5.12); in the cross-check run, XGBoost wins both, and the disagreement mostly disappears.
- **Locked threshold**: 0.377 (primary) vs. 0.43 (cross-check) — a larger, more visible shift than the two above.

This is a known sensitivity of multi-threaded gradient-boosted tree construction to floating-point summation order, which can differ across CPU architectures, thread counts, and library versions even at a fixed random seed — it is not a bug in the code, and it does not affect the paper's substantive conclusions (Section 5.10 and Section 7 Limitations discuss this in full, including the specific package-version deltas most likely responsible). **If you reproduce this pipeline on different hardware and get materially the same AUC and sensitivity but a somewhat different threshold or imbalance-strategy winner, that is expected, not a failure of reproduction.** If AUC differs by more than a few thousandths, something else has changed—check your package versions against Section 4 first.

**What is fully deterministic:** the dataset audit (Section 3), the descriptive statistics and their statistical tests (Table 2), the DeLong test results, and the final reported test-set confusion matrix and everything derived from it (Table 9), since these do not depend on any near-tied optimization step.

## 8. Random Seed and Determinism

A single global seed, `RANDOM_STATE = 42`, is set once at the top of the notebook and threaded through every stochastic operation: the train/test split, all cross-validation fold assignments, every `RandomizedSearchCV` call, every model's internal randomness (e.g., XGBoost's subsampling, Random Forest's bootstrap), and every bootstrap-resampling confidence interval. No other seed is set anywhere else in the codebase. See Section 7 above for what this seed does and does not guarantee across environments.
